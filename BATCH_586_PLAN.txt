   and the Excel export.

without spare profiles retain the existing matrix UI and export behavior.

## Done looks like

### Part A — Measurement model

- Categories are measured only in tiles or square metres.
- Existing staging-only `cartons` settings normalize to `tiles`.
- Unknown measures still return the existing Hebrew 422 error.
- Project settings no longer store or display `per_carton`.
- Every configured profile-aware apartment row gets two UI-only helper inputs:
  cartons and tiles/m² per carton.
- When both helper inputs are present, count becomes the rounded multiplication
  result and the exact Hebrew conversion caption is shown.
- Direct count entry clears both helper fields.
- Clearing either helper field leaves the current count unchanged.
- Custom rows and the no-profile legacy editor remain without the helper.
- Explicit-zero controls, persistence rules, and legacy row ordering remain
  unchanged.

### Part B — Execution Matrix

- `GET /api/execution-matrix/{project_id}` gains one additive top-level
  `spare` object.
- Enabled projects receive a read-only summary per unit: overall, profile,
  short rows, not-entered rows, and missing total.
- Without profiles, `spare.enabled` is false and `spare.by_unit` is empty.
- Desktop gains a conditional final “ריצוף ספייר” column after stage columns.
- Mobile gains a compact spare pill in the card header and a final spare row in
  the expanded body.
- Tapping a pill opens the unit dashboard/defects route with a return path back
  to the matrix.
- A counters strip offers exact one-tap filters for all six statuses.
- The drawer gains a conditional “ריצוף ספייר” group after location.
- Saved views serialize and restore `spare_status`.
- Excel gains a conditional final spare column with Hebrew labels, missing
  details, profile comments, and approved fills.
- Spare data remains derived and read-only; matrix/QC records are never mutated.
